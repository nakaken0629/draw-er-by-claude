# 要件定義書

## 1. 本書の位置づけ

本書は、本プロジェクト（ECサイトのデータモデリング・ER図作成）に着手するにあたり、依頼者（ユーザー）
から提示された要件を、原文の内容を変えずに記録したものである。以降のモデリング・ER図作成・比較検討は
すべて本書の内容を出発点としている。設計上の解釈や判断については、各設計書（design-docs/basic-design/
以下）側に記載し、本書には含めない。

## 2. システムの概要

オンラインで技術書や技術関連のアイテム（USBメモリ、モバイルバッテリーなど技術ガジェットが中心）を
販売するシステム。

## 3. 業務要件

依頼者から提示された要件は以下の通り。

1. 商品を管理する。商品が属するカテゴリも管理する。
2. オンラインで販売履歴を管理する。また、販売に先立って利用者の登録が必要である。登録された
   ユーザーも管理する。
3. 商品の仕入れや出荷を管理する。また仕入れ先も管理する。
4. 仕入れた商品の入庫や売れた商品の出庫を管理する。また月初に在庫の棚卸しを行い、その結果の
   記録も管理する。ある時点での在庫は、毎月この棚卸しの記録に対して、その月に発生した入庫と
   出庫の数で調整したものとする。

### 3.1 要件の内訳（整理用）

| # | 要件領域 | 内容 |
|---|---|---|
| 1 | 商品・カテゴリ管理 | 商品を管理する。商品が属するカテゴリも管理する |
| 2 | 販売・会員管理 | オンラインで販売履歴を管理する。販売に先立って利用者登録が必要。登録ユーザーも管理する |
| 3 | 仕入れ・仕入れ先管理 | 商品の仕入れや出荷を管理する。仕入れ先も管理する |
| 4 | 入出庫・棚卸し管理 | 仕入れた商品の入庫、売れた商品の出庫を管理する。月初に棚卸しを行い、結果を記録する |
| 5 | 在庫算出ルール | ある時点の在庫は、直近の棚卸し記録に対して、その月に発生した入庫・出庫の数で調整した値とする |

## 4. 進め方に関する依頼者からの指示

- まずはClaude単独の力でデータモデリングを行い、結果を `design-docs/basic-design/` 以下に設計書として
  作成する。
- 次に、依頼者が過去に執筆したQiita記事（データモデリングの考え方に関する記事3本）を参考にして
  再度モデリングを行い、両者の結果を比較する。
- モデリング完了後、ER図についても同様に、まずClaude単独の力で作成し、次にQiita記事（特にER図の
  レイアウトに関する記事）を参考にして作成し、両者を比較する。

参考として提示されたQiita記事は以下の3本。

- https://qiita.com/nakaken0629/items/02633743068f217a0429 （テーブルの分類と関連の作り方）
- https://qiita.com/nakaken0629/items/9bd9b519d66fd13f23e0 （ER図のレイアウト原則）
- https://qiita.com/nakaken0629/items/1c67b983b200e19df55b （受注・出荷の多重関連と在庫金額計算の実務的課題）

## 5. 本書のスコープ外

以下は依頼者からの要件として明示されていないため、モデリングの対象外としている（各設計書の
「今後の検討事項」にも個別に記載）。

- 会員のログイン認証情報の管理方法
- 決済・配送業者との連携情報
- 返品・キャンセルに伴う入出庫（逆伝票）の扱い
- 商品の書籍／ガジェットそれぞれに固有な属性（ISBN、著者、保証期間等）の詳細管理
- 複数倉庫（拠点）運用時の在庫管理
- 在庫金額の計算方法（先入先出法・総平均法等の単価決定方式）
