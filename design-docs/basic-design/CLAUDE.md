# データモデリング・ER図作成ルール

このディレクトリ配下でデータモデリングおよびER図作成を行う際は、以下のルールに従う。

## ドメインに依存しないルール

### モデリング

- **テーブル分類を明示する**: 各テーブルを「マスターテーブル」（管理者が登録）「ステートテーブル」
  （利用者が何度も更新する）「トランザクションテーブル」（追加後は基本的に更新されない）のいずれかに
  分類し、設計書上に明記する。
- **トランザクション同士の直接関連を優先する**: 正規化上の必要性だけでなく、業務プロセスの発生順に
  トランザクションを直接関連づける（例: 仕入れ→入庫、受注→出荷）。
- **多対多は中間テーブルで解消する**: 一見1:Nに見える関連でも、分割・まとめ処理（例: 分割出荷、
  まとめ出荷）により実務上は多対多になる場合がある。その際は両者を参照する中間テーブルを新設して
  解消する（「中間テーブルは両方の親が揃わないと作れない」という制約を持たせる）。
- **ステータスは集計から導出し、カラムに持たせすぎない**: 進行状況（未着手／一部実施／完了）は
  関連する実績トランザクションの集計から動的に導出する。ただし取消（キャンセル）のように数量集計
  だけでは表現できない状態は、フラグとして個別に保持してよい。
- **価格等の変動しうる値はスナップショットで保持する**: マスタ側の値が将来変動する場合、取引明細
  には取引時点の値をコピーして持たせ、過去の取引記録が影響を受けないようにする。
- **オーバーエンジニアリングを避ける**: 対称性のためだけに複雑な構造を一律適用しない。仕様文に
  明示される語彙・概念の有無を根拠に構造の複雑度を判断する（例: 「出荷」という語が片側にしかない
  なら、もう片側まで三層化しない）。

### ER図のレイアウト

- **用紙比率はA4横（297:210）に統一する**: エンティティ（ボックス）のサイズは変えず、余白の
  追加・調整でアスペクト比を合わせる。
- **関連線は直角線（鍵型）のみとし、斜め線は使わない**。
- **多重度はER図標準の鳥の足記法で表現する**: 数字ラベル（"1"/"N"）ではなく、直角の短い線（必須の1）
  と鳥の足記号（多）の組み合わせで表現する。
- **配置の原則**: トランザクションは業務の発生順に横へ並べる。ヘッダと明細（親子関係）は縦に並べる。
- **図は注目するモデルで分割する**: 「マスター・ステート一覧図」と「トランザクション系列ごとの図」
  に分け、1枚に情報を詰め込みすぎない。系列を横断した関連を見たい場合は、別途「トランザクション
  関連の統合図」を用意する。
- **色分けはテーブル分類に対応させる**: マスター＝緑、ステート＝黄、トランザクション（中間テーブル
  を含む）＝赤、で統一する。
- **複数から参照されるマスタ・ステートは複製配置するべきである**: 1つのノードに全方向から参照線を
  集中させず、参照元のトランザクションの近くにそれぞれ複製して配置する。一方、トランザクションに
  直接関連しないエンティティ（マスタ経由でしか繋がらないもの）は描画を省略してよい。
- **列情報の粒度は図の目的に応じて絞る**: 詳細な属性を見せる図ではPK/FK＋業務属性を、全体の関連
  構造だけを見せる図ではPKのみに絞るなど、必要最低限の情報量にする。
- **エンティティ名・列名は日本語（論理名）で表示する**: 物理名（英語）はテーブル名の下などに
  補助的に添える。識別子（リレーション定義や分類に使う名前）は英語のまま保持し、表示ラベルのみ
  日本語化する。
- **日本語と半角英数字の隣接に注意する**: Graphviz系のレンダリングでは、同一セル内で日本語と
  半角英数字が隣接すると文字幅の見積もりがずれて重なることがある。セルを分ける、十分なwidthを
  指定する等で回避する。

## ドメインに依存するルール

### 仕入れ・入庫ドメイン

- **仕入れ→入庫は2層構造とする**: 仕入れ（発注）に対して入庫（実績）は1:N（分納対応）。仕入れ側に
  「出荷」に相当する多重関連が仕様上存在しない限り、三層化はしない。

### 販売・出荷ドメイン

- **受注・出荷・出庫は3層構造とする**: 受注（受注明細）と出荷は実務上多対多になるため、「出庫」を
  受注明細と出荷の両方を参照する中間テーブルとして置き、分割出荷・まとめ出荷の両方を表現する。

### 在庫・棚卸しドメイン

- **在庫数は常時テーブルに保持せず、動的に算出する**: `在庫数 = 直近の棚卸し記録の実棚卸数量
  + それ以降の入庫数量の合計 − それ以降の出庫数量の合計`。
- **棚卸しは独立した系列として扱う**: 月初に実施し、商品ごとの実棚卸数量を記録する。他のどの
  トランザクションとも直接関連せず、商品マスタのみを介して間接的に在庫算出ロジックと結びつく。
